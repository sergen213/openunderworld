# Roadmap and status

Status vocabulary: **Research Required → Designed → Implemented → Tested → Verified Against Original Behavior**.
A feature is only "Tested" with automated tests in `tests/`, and only "Verified" with a recorded comparison to the original game.

## Milestones

| # | Milestone | State |
|---|---|---|
| 1 | Environment, project audit, research, repo + docs | Done (ENVIRONMENT, EXISTING_PROJECT_AUDIT, RESEARCH, ROADMAP; kept current per release) |
| 2 | Original game analysis: inventory, Ghidra, verified parsers | Done for the GOG 1.1.0.0 build (importer manifest, Ghidra project, format docs in docs/formats); research continues per system |
| 3 | Native rendering: SDL3 + OpenGL viewer of original assets, debug camera | Done (`ou-viewer`, GL + Vulkan) |
| 4 | Engine foundations: scene/streaming, animation, collision, character control | Done; fidelity work per system continues (compatibility matrix) |
| 5 | Playable section: traversal, puzzles, combat, saving | Playable from chapter 0 to the credits (`ProgressionReal.CriticalPathInOrder`); open items per row below |
| 6 | Vulkan backend, enhanced rendering, optional RT | Done (Vulkan 1.3 at GL parity; RT shadows, reflections, AO / GI; FSR 3.1 upscaling + frame generation) |
| 7 | Qt launcher, packaging, CI, signed updates | Done (Qt 6 launcher, AppImage in Ubuntu 24.04 container, CI, Ed25519-signed updates) |
| 8 | Edition compatibility, fidelity verification, release | In progress: only the GOG 1.1.0.0 build is available for testing; other editions untested |

## Planned: Jolt Physics (replaces our Havok stand-ins)

The original game uses Havok. Our hand-written hinge/prismatic solver and the bike's fitted numbers were stand-ins; steps 1 and 2 replaced them.
[Jolt Physics](https://github.com/jrouwe/JoltPhysics) (MIT) is vendored at a pinned release tag through CMake
`FetchContent` with `CROSS_PLATFORM_DETERMINISTIC` on, so replays and tick-by-tick tests stay bit-exact. Lara's
controller and the level collision queries stay ours (Lara moves kinematically from root motion; Jolt's CharacterVirtual
was evaluated as her mover and not adopted: docs/formats/PHYSICS.md "Character controller"); level collision is fed to
Jolt as static mesh shapes per streamed unit.

1. **Joints and rigid bodies (done, docs/formats/PHYSICS.md).** `physics::Scene` keeps its interface; inside it, Jolt
   bodies come from the HInfo spheres / boxes / capsules with the exe's mass and inertia. Hinge and prismatic joints are
   Jolt constraints with the data's limits and motors; the uber-object range watches (triggers 14 / 15) read the
   constraint positions. Loose bodies and grapple-pulled weights tumble and stack. Pressure plates are Jolt bodies on
   their prismatic joints, weighed by contacts (loose bodies) and by Lara / push blocks standing on them; Lara's
   velocity-driven proxy shoves loose bodies and ragdolls; push blocks stay grid driven, colliding as kinematic bodies.
   Not done: fixed joints and body A motion; the plates' Havok motor numbers [I]. Acceptance met:
   every `ProgressionReal` gate and `game_render_rate_smoke` pass; tests that pinned our own solver numbers were
   rewritten to the data's behaviour.
2. **Motorcycle (done, docs/GAMEPLAY.md "Motorcycle", PHYSICS.md "Vehicles").** The bike's Havok vehicle data is
   decoded (wheel definitions on the model's spheres / markers, springs, the record's engine and its one gear, brakes,
   tilt limit); the ridden bike is a Jolt `VehicleConstraint` with ray wheels and tru.exe's engine as wheel forces on
   the level collision; jumps, ramps, landings and crashes come out of the simulation; saves continue bit for bit.
   Not done: the air control torques, wheelies / power slides / donuts, the lean (servoed upright, not drawn); hop and
   ram stay [I].
3. **Ragdolls (done, docs/formats/PHYSICS.md "Ragdolls").** Dead enemies become Jolt ragdolls from their object's
   ragdoll record (ObjectBase +0x7C: capsule per bone, hinge / two-axis / cone-twist joints with the data's limits) when
   the death timer runs out (the death entry's min..max counts, 0x66C500), mid-clip, with the killing hit's impulse;
   thralls break into their `*_chunkdoll` pieces instead (death record +0x46: loose bodies at the body's segments,
   pushed along the hit). Lara ragdolls from her record once her death clip is done. They land on the terrain,
   colliders and loose bodies, freeze when asleep and save bit for bit (`GameReal.KilledPoacherRagdollIndependentOfRenderRate`,
   `GameReal.LaraRagdollIndependentOfRenderRate`, `GameReal.KilledThrallBreaksIntoChunks`, `AiReal.DeathTimerAndThrallChunks`,
   `StreamReal.RagdollSaveLoad`, `Physics.RagdollFallsDownAStepJointsHoldAndSaves`). No clip blend: the original's
   death takeover is unpowered. Open [U/I]: which Lara deaths ragdoll at once (death types 3 / 4), her 3 s reload
   after the ragdoll, chunk flags and fading, the count unit (30 Hz).


## Principles

- Fixed-step simulation (60 Hz initial hypothesis, to be verified against the original main loop) with render interpolation.
  Nothing that can change gameplay may read frame time or the rendered camera: physics, movers, scripts, AI and effects
  tick at 60 Hz only (audit table: docs/GAMEPLAY.md "Timing"; real-puzzle tests bit-identical tick by tick at 24–1000 Hz,
  irregular frames, and ctest `game_render_rate_smoke`).
- Gameplay/simulation independent of the render backend; both renderers consume `src/scene/Assets.hpp` data.
- Original Fidelity and Enhanced rendering modes; ray tracing optional with raster fallback.
- Original installation is read-only; no copyrighted data in the repo or releases.
